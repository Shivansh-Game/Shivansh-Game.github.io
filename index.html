When Can You Safely Delete Layers from an LLM?

Paper Title: Applicability of Static Layer Pruning in LLMs Relating to Training Tokens Per Parameter

The Plain-English Summary

A popular trick to shrink an LLM without retraining it is to simply delete ("prune") a few layers that barely change the output. That worked great on older LLMs. Why does it fail badly on newer models? I tested 125 models (Pythia 410M–6.9B and OLMo-1B, trained on up to 3.05 trillion tokens) and found a simple rule: the more training tokens you pack into each parameter, the less "free space" the model has left. Lightly trained models have plenty of lazy layers at the end that you can delete for free. Heavily trained models use every single layer to store knowledge—so deleting even 2 layers breaks them.

What Happens Up to 3.05 Trillion Tokens?

I tracked OLMo-1B (16 layers) across 9 training checkpoints from 23 billion tokens (1×) all the way to 3.05 trillion tokens (128×). It goes through 3 clear stages:

  • 1. Early Learning (1×–4×): As training starts (23B–96B tokens), layers start taking on specific jobs.
  • 2. Safe Flat Zone (4×–32×): From 96B to 768B tokens, deleting 2 layers stays totally steady—only hurting perplexity by 16%–18%.
  • 3. The 128× Cliff (3.05T Tokens): Once you pack 3.05 trillion tokens into a 1B model, it runs out of spare layers. Deleting 2 layers jumps 4× higher to +69.5% error, and deleting 8 layers ruins the model (+7,160%).

Do Transformers Follow Rules They Know, or Take Lazy Shortcuts?

Paper Title: Learning Local Rules Without Global Invariants: Out-of-Distribution Shortcut Learning in Autoregressive Transformers

The Plain-English Summary

Imagine playing a game with binary strings where every single step must flip exactly 2 bits. Because you always flip 2 bits at a time, after 3 steps you can only land an even number of bits away (0, 2, 4, or 6 bits). You can never land 1 bit or 3 bits away! I trained Transformers across a 170× size range (58K to 9.94M parameters) so they learned the 2-bit step rule with 100% accuracy. Then I asked them: "Can you reach a string that is only 1 bit away in 3 hidden steps?" Every single model got 0% accuracy—saying "Yes" 100% of the time! Instead of checking if the distance was even, the models learned a lazy shortcut: "Is the distance 6 or less? Say Yes!" Even crazier: the model actually does build an even/odd checker in Layer 2, it just turns it off when middle steps are hidden.

Paper 03 • Double-Blind Review Sole Author

Skipping 8 Layers in One Jump to Run LLMs Faster on Everyday GPUs

Research Paper on Hardware-Constrained LLM Inference (Currently under double-blind review)

The Plain-English Summary

Not every word an LLM generates needs all 28 layers of deep thinking. Writing the or is is much easier than solving a hard math step! Other methods try to skip layers one at a time, which actually slows the GPU down because it has to stop and check a router at every single layer. Instead, I built a small Predictor + Gate at Layer 16 of Llama 3.2 3B (trained in just 1.5 hours on a single A100 GPU without touching the base model weights). When a token is easy, it jumps straight from Layer 16 to Layer 25—skipping 8 layers in one clean leap and skipping their KV cache writes completely!

The KV Cache Notebook

Skipped Words Leave Empty Cubbies, Not Shifted Seats

Green = a note exists • Dashed Coral = that word skipped the layer, so no note was written • Top numbers = each word's real global position (RoPE)

The cache is called ragged because it has missing spots. The model skips those spots and keeps reading the notes that are there. Layers 25–28 then finish the word with the whole picture back together.

1. The Notebook

Think of the KV cache as a notebook. For every word, the model writes a little note at every layer so it never has to redo the same work.

2. The Empty Cubbies

When a word is easy, Layers 17–24 are skipped for that word. No note is written there, so the notebook gets empty spots. That is the “ragged” cache.

3. The Seat Numbers

Every note keeps the word's real seat number (its global position). An empty seat 3 does not make word 4 slide into seat 3, so distances still make sense.

4. One Word at a Time

When the model writes one new word, it reads all the notes that already exist. There are no future notes to hide, so it does not need a mask. Layers 25–28 then bring the full picture back.

04 • Engineering & Open Source

Custom GPU Kernels & Open Source Fixes

OpenAI Triton • Custom GPU Kernel Up to 1.18× Faster Token Generation

Fused SwiGLU Kernel in OpenAI Triton

The Problem: A GPU has two kinds of memory: huge main memory (DRAM, which is slow to travel to) and tiny on-chip memory right next to the math cores (SRAM, which is super fast). When standard PyTorch runs the SwiGLU layer inside an LLM, it sends data back and forth to slow DRAM several times for each step.

What I Built: I wrote a custom GPU kernel in OpenAI Triton that pulls the data into fast on-chip SRAM once, does both the SiLU activation and the multiplication right there on the chip, and writes the final answer back to DRAM just once—making token generation up to 1.18× faster.

Model Architecture Bug Found Stanford HazyResearch

HazyResearch / ncm

Investigated a non-autoregressive language model (a model that generates several words at the same time instead of one by one) built by Stanford researchers. I discovered that its generator module mixes up which description belongs to which noun inside the same chunk of words, and used the team's official checkpoints to prove this flaw remains even at the end of training.

Key Takeaway:
Generating words in parallel inside a chunk causes the generator to swap attributes between nearby objects.
Open Source Bug Fix + Tests nltk / nltk

Natural Language Toolkit (NLTK)

Fixed a bug in NLTK's popular word_tokenize function where em-dashes (—) were treated like regular hyphens, leaving two separate words stuck together as one token. Added unit tests to keep it fixed.
